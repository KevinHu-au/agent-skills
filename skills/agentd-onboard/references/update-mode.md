# Update mode

Used when `docs/onboarding/README.md` already exists. The code is the source of truth. Refresh only what is outdated, and keep what the code cannot contradict. Run every git command in this file from the repository root: `cd "$(git rev-parse --show-toplevel)"` first, or use `git -C "$(git rev-parse --show-toplevel)"` if the shell does not keep the folder. Work through these steps in order.

1. **Read the header.** Take `Scanned commit` from the top of `README.md`. If the file has none of the three header lines and no `## First-ticket checklist` heading, it is not a pack: someone else wrote it. Stop as `SKILL.md` Modes says, and do not change it. If `Scanned commit` is missing or garbled (not 7 to 40 hex characters, for example because someone edited the header by hand), do a full re-check of every section, and say so in the `Last refreshed:` line. Do not stop and do not skip the refresh. If the header says `Working tree: dirty`, the scanned commit did not describe what was read last time. Add the files that Unknowns lists as uncommitted to the list in step 3, because they may have changed since. If Unknowns lists none, do a full re-check.
2. **Check that the commit exists.** Run `git cat-file -e <commit>^{commit}`. If it fails, no diff is possible: the clone is shallow, history was rebased, or the repository has no commits. Do a full re-check and say why in the `Last refreshed:` line.
3. **List what changed.** Run `git diff --name-only --no-renames <commit>..HEAD -- . ':(exclude)docs/onboarding'` for committed changes. The `--no-renames` flag lists the old path of a renamed file as well as the new one. Add the uncommitted files from `git status --porcelain --no-renames --untracked-files=all -- . ':(exclude)docs/onboarding'`, which prints `XY path` lines (two status letters, a space, then the path, so drop the first three characters), including the files inside untracked folders. Git quotes a name that has spaces or non-ASCII characters, in this command and in `git diff --name-only`. Add `-z` to either command to get unquoted, NUL-separated names. Leave out `docs/onboarding/`: the pack itself is not a source, and without the exclusion a second run on an untouched repository would see its own files as changes. Also leave out what this skill wrote itself. A change to `AGENTS.md` counts only if a hunk lies outside its `## Project contract` section: check with `git diff -U0 <commit> -- AGENTS.md`. An `AGENTS.md` that this skill created, and that holds only that section, does not count. Build output from approved safe checks (`bin/`, `obj/`, `node_modules/`) does not count when the repository does not ignore it. Compare these paths with the paths in each section's `Sources:` line, ignoring the `:line` part. A folder in `Sources:` matches every file under it. A path vanishes when a `Sources:` line names it and it no longer exists in the working tree. Treat a vanished path as changed.
4. **Pick the sections to re-check.** Re-check a section when a path in its `Sources:` line changed or vanished. Side files count as part of the section they extend. A changed path that no `Sources:` line names also counts: decide what it is and re-check the section it belongs to:
   - an endpoint, screen or handler: Use cases, and External systems if it reaches an integration
   - a document or user guide: the section it describes (a user guide for a feature: Use cases)
   - a schema script, entity or stored procedure: Data model
   - a project, build or configuration file: Architecture and patterns, and Run and verify
   - a pipeline or deployment file: Risks and delivery
   - an integration client: External systems

   The checklist and Unknowns have no `Sources:` line. Refresh them last, from the other sections. If no section was picked, go to step 8.
5. **Replace what the code contradicts.** Read the changed and cited files, not the whole repository. For a full re-check, follow Flow step 2 in `SKILL.md` (explorers, or the sequential fallback), or read the files directly when the repository is small. Otherwise start the fitting explorer angle only if many files changed. When the brief disagrees with the code, replace the brief text with what the code says and mark it `changed:`. Keep the facts the code cannot contradict: owners, business meaning, answers the engineer or the customer gave, and `unknown:` entries nobody has answered yet. Do not ask a question again that has an answer. Before you mark anything, remove every `changed:` marker an earlier refresh left, in every section and side file, so `changed:` always means the last refresh. That is the only edit allowed outside the sections you re-check. Refresh the facts of the `## Project contract` section of `AGENTS.md` that the code can check, as `contract-fill.md` says, and ask before editing it.
6. **List stale notes in other documents.** When another document disagrees with the code, such as a wiki README with an old runtime version, do not edit it. List it as a finding, with both sources, in `Unknowns` and in `open-questions.md`. Use the code's value in the brief and mark a disagreement `conflict:`.
7. **Update the header and add the note.** Set `Scanned commit` to the full output of `git rev-parse HEAD`, `Scanned on` to today, and `Working tree` to `clean` or `dirty`, using the same exclusion as step 3. Add one `Last refreshed:` line directly under `Working tree:`. It holds the date and one line on what changed. If this was a full re-check, say why. Replace the previous `Last refreshed:` line instead of adding another. Update the two scan lines in each side file the same way. Write commit ids inside the `Last refreshed:` line as 7 to 12 characters. The note is a header line, not a heading. A new H2 would need its own `Sources:` line and would break the fixed headings.
8. **If nothing needed a change, write nothing.** When no section was picked and no stale note is new, write nothing to any file, not even the header date or the scanned commit. Report `No changes since <commit>.` The next run diffs from the same commit, so nothing is lost. The contract is the one exception: if an earlier run did not write it and you can ask now, follow `contract-fill.md` even when the brief needs no change.

An example of the note:

```
Last refreshed: 2026-10-22: changed: added the cancel use case and moved the runtime to net9.0 (scanned 76e5663 to 7d59182)
```
