# Update mode

Used when a marked `verify-*/SKILL.md` already exists. The code is the source of truth. Edit only the verify skill's folder. Run every git command in this file from the repository root: `cd "$(git rev-parse --show-toplevel)"` first. Work through these steps in order.

1. **Find the skill and check the marker.** Look for `verify-*/SKILL.md` under any `.github/skills/` or `.claude/skills/` folder. Accept a file only when its header holds the two marker lines (`metadata:`, then `  generated-by: agentd-verify-init`, nested with two spaces). A `verify-*` skill without them is not generated by this skill. Ignore it. If no marked skill is left, stop and change nothing. When several marked skills match, list them and ask which one.
2. **Read the folder.** Read the skill's `SKILL.md`, `features/README.md`, every feature file, `data-setup.md` and the helpers. Take `Scanned commit` from the top of `features/README.md`. If it is missing or garbled (not 7 to 40 hex characters), do a full re-check of every feature file, and say so in the report. Run `git cat-file -e <commit>^{commit}`. If it fails (a shallow clone, a rebased history), do a full re-check and say why.
3. **List what changed.** Run `git diff --name-only --no-renames <commit>..HEAD -- . ':(exclude)<the verify skill folder>'` for committed changes. Add the uncommitted files from `git status --porcelain --no-renames --untracked-files=all`, which prints `XY path` lines (drop the first three characters). Leave out the verify skill's own folder. Leave out the paths in the `LocalOnlyFiles` list of `common.ps1` (read the list, never the file content). Do not use the per-ticket `appFingerprint` in `state.json` for this: it is a hash and cannot list files. A path that a feature file names, or a Code folder, and that no longer exists counts as changed.
4. **If nothing changed, stop and change nothing.** When no code changed and the skill carries no `draft: not proven` line, write nothing to any file, not even the date. Report `No changes since <commit>.` The next run diffs from the same commit, so nothing is lost. When the skill does carry the draft line, go to step 8.
5. **Re-check the map against the code.** Re-check the `Code folders` column of `features/README.md` too: add the column when the file has none, and fill each row from the code. Match each changed path to the feature files that name its routes, labels and steps. Read the changed code, not the whole repository. Where a feature file disagrees with the code, replace the file text with what the code says and mark it `changed:`. Remove every `changed:` marker an earlier update left first, so the marker always means the last update. Keep what the code cannot contradict: setup recipes, gotchas from earlier runs, and `unknown:` entries nobody has answered. Add a feature that is new and has a user route. With the engineer, drop a feature the code no longer has. Check the helpers against the harness too: ports, start commands, the image tag.
6. **Drive every feature once.** With the engineer present: launch, sign-in, Doctor, then drive each feature file once and capture evidence. Run cleanup, then check the evidence folder still exists. A step that fails because the map is wrong is a skill fix: correct the file and mark it `changed:`. A step that fails because the app does not do what its own screen or user document says is a product regression. Do not fix product code.
7. **List the findings in two parts.** List map corrections and helper fixes first. List product regressions apart, each with the feature, the step, what was seen, the evidence file, and `path:line` for the code. Say what you could not drive and why, under `unknown:`. Then update the two scan lines at the top of `features/README.md`: set `Scanned commit` to the full output of `git rev-parse HEAD` and `Scanned on` to today. The engineer will commit through the normal PR.
8. **Promote a proven draft.** When the skill carries `draft: not proven` and a `Not proven:` list, run the proof run: launch, sign-in, Doctor, one feature, evidence, cleanup, then check the evidence folder still exists. It needs the engineer present, because the engineer signs in. If every step passes, remove the `draft: not proven` line and the `Not proven:` list. After a passing proof run, replace each `unknown:` and `inferred:` gotcha that the run confirmed or refuted with the result, and remove the fixed-port text for any port the run found unused. If a step still cannot run, keep both, and update the list to the steps that did not run. Never remove the draft line without a passing proof run.

An example of the findings, with placeholders:

```
Map corrections: <feature-a>.md: changed: the menu item moved under <menu>.
Product regressions: <feature-b>, step 3: the total shows <x> where the user guide says <y> (evidence: <file>; <path>:<line>).
Not proven: none. The draft line was removed after the proof run passed.
```
